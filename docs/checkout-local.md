# בדיקת נגישות והזמנות מקומית

פריסת האתר ותשתית ההזמנות אושרה במפורש ב־22 בנובמבר 2026. סביבת הבדיקה המתוארת כאן נשארת מבודדת מהנתונים החיים.

## פתיחה

להפעיל משורש הפרויקט: `npm run dev` (או `powershell -ExecutionPolicy Bypass -File tools/start-next.ps1` במחשב הנוכחי).

- חנות עם מוצרי דוגמה ומלאי: `http://localhost:3000/?local-orders=1`.
- אדמין לאותם נתוני בדיקה: `http://localhost:3000/admin?local-orders=1#orders`.
- יציאה מהבדיקה וחזרה לקטלוג המחובר לשרת: `http://localhost:3000/?local-orders=0`.

יש להשתמש באותו host ובאותו דפדפן בשני המסכים. `localhost` ו־`127.0.0.1` מחזיקים אחסון נפרד. מצב הבדיקה נשמר ב־sessionStorage; הקטלוג, המלאי וההזמנות המקומיים נשמרים ב־localStorage במפתח `snapir-local-store-v1`. הסל המקומי נפרד מהסל הרגיל. המצב חסום בכל hostname שאינו loopback, גם אם מוסיפים את הפרמטר לכתובת ציבורית. הנתונים מקומיים ודמה בלבד, ללא התחברות למשתמש מנהל אמיתי. השתמשו בפרטי בדיקה בלבד.

## התהליך

הוספת מוצר ומשקל לסל, מעבר להשלמת הזמנה, פרטי קשר, בחירת משלוח או איסוף, כתובת במשלוח בלבד, בדיקת סכום ואישור שליחה. מתקבל מספר הזמנה והסל מתנקה רק לאחר אישור השרת. אין תשלום אונליין ואין הודעות WhatsApp/אימייל אוטומטיות.

באדמין: הזמנה חדשה ממתינה לאישור → אושרה ובטיפול → מוכנה → נשלחה → הושלמה. באיסוף עצמי מדלגים מ־מוכנה ל־נאספה והושלמה. ביטול מחזיר מלאי פעם אחת. אפשר לעדכן שליח, מספר מעקב ותאריך אספקה.

הסל שומר מזהה מוצר, משקל אריזה וכמות. סל ישן ללא מזהים אינו נשלח בטעות; יש לבחור את המוצרים מחדש. מחירים, חיתוכים, משקלים, קטגוריות ומלאי מאומתים שוב לפני שליחה. בקשה שתשובתה אבדה שומרת את אותו מזהה ותוכן ב־sessionStorage עד ניסיון חוזר, גם אחרי רענון. אין נתוני לקוח בשורת הכתובת או באישור הציבורי.

## Supabase — הותקן במסגרת הפריסה המאושרת

`supabase/migrations/20261122192548_storefront_checkout.sql` הוא המיגרציה שהותקנה בפרויקט החי. הוא מוסיף מקור ואופן קבלה להזמנות, RPC ציבורי צר ליצירת הזמנה, וחיבור למערכת ההרשאות וההזמנות הקיימת. טבלאות הלקוחות וההזמנות נשארות מוגנות ב־RLS, ללא SELECT ציבורי. המחיר מחושב רק בשרת; סכום הלקוח הוא תנאי לאישור ולא מחיר סמכותי. המלאי והלקוח נכתבים יחד בטרנזקציה. יש נעילה לפי מזהה בקשה, סדר נעילות מוצרים עקבי, בדיקת משקלים וחיתוכים מפורסמים, והגבלה בסיסית של חמש הזמנות לטלפון ב־15 דקות. לפני חשיפה ציבורית יש לבחון הגנת ספאם בהתאם לתשתית ההפצה; ההגבלה לפי טלפון אינה זיהוי של לקוח.

המיגרציה הופעלה באישור הפריסה, ובדיקות ההרשאות ו־advisors הושלמו. כדי לקבל הזמנות בפועל צריך לעדכן מלאי ולפרסם שיטות משלוח עם כתובות/אזורי חלוקה ועלויות אמיתיים. אין להפעיל שוב מיגרציה שכבר הותקנה.

## נגיש לי

המקור הרשמי: https://www.nagish.li/download.html . הותקנה מקומית גרסת 3.0 Beta כפי שהופצה, עם כל הרישיונות והקרדיטים. התוסף עצמו לא שונה. ההפצה מציינת שחלק מהאפשרויות עדיין אינן זמינות; אין מצג של אישור נגישות מלא.

שכבת האתר מטפלת ביחס גודל הכותרות והטקסט, SVG, סגירה במקלדת, סימון פתוח/סגור, חסימת פוקוס ברכיב סגור, הצהרת הנגישות, ניגודיות ומידות במובייל. קוד החנות עטוף בסקופ פרטי כדי שלא להצל על `$` של jQuery שבו משתמש מנגנון ההודעות של התוסף. קישור דילוג לתוכן נוסף גם ללא פתיחת הרכיב.

## בדיקות

- `python tests/verify_next.py`: עשרה עמודים, בדיקת hash של קבצי הספק, מקלדת, הגדלה פרופורציונלית, ניגודיות תפעולית/הדגשת קישורים, שמירה, איפוס, הצהרה ומובייל. זו אינה בדיקת תאימות מלאה לתקן.
- `python tests/verify_next.py`: חנות → סל → איסוף/משלוח → אישור → אדמין → סטטוסים/ביטול, מלאי, מובייל, שינוי זמינות, ושחזור אחרי אובדן תשובת שרת בלי כפילות. החיבור החי חסום בבדיקה.
- `python tests/verify_database.py`: בדיקות האדמין הקיימות, ועוד SQL ב־PostgreSQL WASM מבודד עבור RPC לקוח, הרשאות, פרטיות, מחירים, משקל/חיתוך, כתובת, idempotency, rollback, הגבלת בקשות והחזרת מלאי.


ההטמעה הפעילה הועברה ל־Next.js: תהליך ההזמנה נמצא ב־`components/checkout.jsx`, הסל והקטלוג ב־`components/store-provider.jsx`, והנתונים המקומיים ב־`lib/local-store.js`. גרסת ה־HTML הקודמת נשמרת ב־`legacy/` לעיון בלבד.
